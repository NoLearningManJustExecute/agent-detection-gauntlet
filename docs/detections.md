## Content tier

### ADG-0002: Injection phrasing in retrieved or tool-result content

- **Version:** 0.1.0 (experimental), **severity:** medium
- **Logic:** match
- **Telemetry:** retrieval, tool.result
- **Mappings:** ATLAS AML.T0051.001; OWASP LLM LLM01; OWASP Agentic ASI01; ATT&CK none
- **Fixtures:** 3 tp, 5 fp

Fires on text in a retrieval or tool result that addresses the agent with override or imperative phrasing, after NFKC normalization, case folding and whitespace collapse.

**Hypothesis.** Injected instructions tend to reuse a small set of override idioms. A normalized phrase list is the honest keyword baseline: it should catch authored injections and lose recall as soon as the wording is paraphrased or translated.

**Limitations.**

- The phrase list is English. A translated or paraphrased injection with the same effect does not match.
- Documents that discuss prompt injection, or legitimately say 'you must use' or 'always use' in instructions to a human reader, match the same phrases.
- It reads adg.content.text only, so an encoded or split payload is invisible until something decodes it.

### ADG-0003: Credential pattern in tool call arguments

- **Version:** 0.1.0 (experimental), **severity:** high
- **Logic:** match
- **Telemetry:** tool.call
- **Mappings:** ATLAS AML.T0057; OWASP LLM LLM02; OWASP Agentic ASI02; ATT&CK none
- **Fixtures:** 2 tp, 5 fp

Fires when any string in a tool call's arguments holds a credential-shaped value: the lab's sandbox canary format, or common token and key formats.

**Hypothesis.** A secret that reaches tool arguments has left the model's context for a system that may record or forward it, whichever tool is called and whatever the prompt said. Matching the value rather than the request should hold when the request wording changes, and fail when the value itself is transformed.

**Limitations.**

- The canary format and the service_token name are specific to the sandbox, and every dev hit comes from one of those two. The generic token patterns have no dev evidence and miss unstructured secrets.
- A value that is encoded, spaced out or summarized before it reaches the arguments does not match.
- A legitimate call that names a credential field, such as a query about how service_token rotation works, matches.

### ADG-0004: Encoded blob in outbound tool arguments

- **Version:** 0.1.0 (experimental), **severity:** medium
- **Logic:** match
- **Telemetry:** tool.call
- **Mappings:** ATLAS AML.T0057; OWASP LLM LLM02; OWASP Agentic ASI02; ATT&CK none
- **Fixtures:** 1 tp, 5 fp

Fires when an outbound tool call's arguments hold an unbroken base64 or hex run of at least 24 characters.

**Hypothesis.** Encoding hides content from filters and from a human reviewer, and ordinary mail text has no reason to hold a long unbroken base64 or hex run. Presence of the blob should be visible even when its meaning is not.

**Limitations.**

- Long identifiers, hashes and URL paths match; so would a legitimate attachment sent inline.
- A blob split with spaces or line breaks into runs under 24 characters does not match, and neither does an encoding outside these alphabets.
- The outbound tool list is a name pattern, so a renamed sink is not covered.

### ADG-0005: Instruction-like text in tool metadata

- **Version:** 0.1.0 (experimental), **severity:** high
- **Logic:** match
- **Telemetry:** retrieval
- **Mappings:** ATLAS AML.T0051.001; OWASP LLM LLM01, LLM03; OWASP Agentic ASI04; ATT&CK none
- **Fixtures:** 3 tp, 5 fp

Fires when a retrieved tool definition holds text that instructs the agent, rather than describing the tool: mandatory wording, ordering demands, deprecation of another tool, or concealment.

**Hypothesis.** A tool description exists to describe parameters. Imperatives aimed at the agent, or claims that another tool is deprecated, are how tool metadata hijacks a session, so the wording should separate poisoned definitions from ordinary ones while it stays in English.

**Limitations.**

- The phrase list is English, so a translated poisoned description does not match.
- Honest tools can say 'deprecated' or 'you must supply a path'; those definitions match.
- It inspects definitions when they are retrieved. A definition that changes after the trace starts is seen only if it is retrieved again.

### ADG-0006: Override or concealment phrasing in the user prompt

- **Version:** 0.1.0 (experimental), **severity:** medium
- **Logic:** match
- **Telemetry:** user.prompt
- **Mappings:** ATLAS AML.T0051.000, AML.T0054; OWASP LLM LLM01; OWASP Agentic ASI01; ATT&CK none
- **Fixtures:** 2 tp, 5 fp

Fires when a user prompt claims a system role, suspends rules, asks the agent to hide what it did, or asks it to decode a value before acting.

**Hypothesis.** Direct attacks usually have to argue the agent out of its instructions or out of telling the user. Those arguments reuse recognizable phrasing, so a normalized list should catch authored direct attacks and degrade on paraphrase and translation.

**Limitations.**

- The phrase list is English, and most direct attacks that succeed in the dev split use ordinary requests with no override wording at all.
- Benign prompts that quote or rewrite such phrases match, as do prompts about base64 or asking for a reply that does not mention something. The dev benign set has such prompts.
- It says nothing about whether the agent complied.

## Sequence tier

### ADG-0001: Untrusted retrieved content flows into an external send tool call

- **Version:** 0.1.1 (experimental), **severity:** high
- **Logic:** sequence: untrusted_retrieval, then external_send
- **Telemetry:** retrieval, tool.call
- **Mappings:** ATLAS AML.T0051.001; OWASP LLM LLM01; OWASP Agentic ASI01; ATT&CK none
- **Fixtures:** 2 tp, 7 fp

Fires when a retrieval marked untrusted is followed, in the same trace, by a tool call to an external-send sink whose content derives from that retrieval. Derivation follows the adg.content.ref provenance chain transitively, so the retrieved text can pass through model requests and responses before it reaches the tool arguments.

**Hypothesis.** Indirect prompt injection that causes harm needs two things in the same session: attacker controlled text entering the context through retrieval, and the agent acting on it through a tool that reaches outside the trust boundary. The rule keys on that provenance path rather than on the wording of the injected text, so it should hold up under paraphrase, translation, encoding, and other payload mutations that leave the data flow unchanged.

**Limitations.**

- Depends on instrumentation recording adg.content.ref. A missing link hides the flow and the rule misses. Coarse provenance that marks every output as derived from all prior context makes the rule fire on any send after an untrusted retrieval.
- The sink list is a fixed set of tool names. Renamed tools, new send tools, and indirect channels such as writing to a shared file that another process sends are not covered.
- The rule cannot judge intent. A user who deliberately forwards untrusted content, such as a public article, produces the same data flow and the rule fires.
- The rule fires whether or not the send succeeded or was blocked downstream by a guardrail.
- The dev split shows the source and sink lists matter: tool metadata counts as a retrieval, but untrusted tool results and a poisoned send tool are not covered here. ADG-0009 and ADG-0012 cover those.

### ADG-0007: Untrusted read, then secret read, then external send

- **Version:** 0.1.0 (experimental), **severity:** critical
- **Logic:** sequence: untrusted_read, then secret_read, then external_send
- **Telemetry:** retrieval, tool.result, tool.call
- **Mappings:** ATLAS AML.T0051.001, AML.T0053; OWASP LLM LLM01, LLM02; OWASP Agentic ASI01, ASI02; ATT&CK none
- **Fixtures:** 1 tp, 5 fp

Fires when one trace reads untrusted content, later reads data labeled secret or pii, and later still calls an outbound tool.

**Hypothesis.** An exfiltration driven by injected content needs all three steps in this order. The order does not depend on wording, so it should survive payload mutations that leave the tool sequence alone.

**Limitations.**

- The dev split holds no trace with this shape, so the true positive fixture is synthetic and the rule is unproven on real traces.
- It needs no data link between the steps, so a task that happens to do all three in order fires.
- It depends on instrumentation labeling trust and sensitivity. An unlabeled read hides the step and the rule misses.
- An attack that takes the secret from the system prompt rather than a tool result has no secret read step and is not covered.

### ADG-0008: Secret read followed by an external send

- **Version:** 0.1.0 (experimental), **severity:** high
- **Logic:** sequence: secret_read, then external_send
- **Telemetry:** tool.result, tool.call
- **Mappings:** ATLAS AML.T0057; OWASP LLM LLM02; OWASP Agentic ASI02; ATT&CK none
- **Fixtures:** 1 tp, 5 fp

Fires when a trace reads data labeled secret or pii and later calls an outbound tool, with no untrusted precondition.

**Hypothesis.** Sending after reading sensitive data is the shape of exfiltration whether the instruction came from a document or from the user, so dropping the precondition should reach direct attacks at a cost in false positives.

**Limitations.**

- In the dev split it fires only on failed attacks of the ineffective class AC03, so its true positive fixture is synthetic and the rule is unproven on a successful real trace.
- A user who reads a credential file and then sends an unrelated message produces the same sequence, since the rule does not check that the secret reached the send.
- Secrets taken from the system prompt or from memory are not labeled tool results and are not covered.

### ADG-0009: Untrusted content flows into a write or send tool call

- **Version:** 0.1.0 (experimental), **severity:** high
- **Logic:** sequence: untrusted_content, then write_call
- **Telemetry:** retrieval, tool.result, tool.call
- **Mappings:** ATLAS AML.T0051.001, AML.T0053; OWASP LLM LLM01, LLM06; OWASP Agentic ASI01, ASI02; ATT&CK none
- **Fixtures:** 1 tp, 5 fp

Fires when a write, destructive or outbound tool call derives, through adg.content.ref, from content marked untrusted, whether it came from a retrieval or a tool result.

**Hypothesis.** Acting on injected content leaves a provenance link from the untrusted text to the action. Keying on that link rather than on wording should hold under paraphrase as long as enough text is copied verbatim to produce the link.

**Limitations.**

- adg.content.ref comes from verbatim overlap of at least K characters (K=24 here). A rewrite of the untrusted text breaks the link and the rule misses.
- A user who deliberately asks to forward untrusted content produces the same flow.
- The write tool list is a name pattern, so a renamed tool is not covered. The corpus has only send tools, so the write and destructive names are untested.

### ADG-0010: Secret-bearing tool call after untrusted content

- **Version:** 0.1.0 (experimental), **severity:** high
- **Logic:** sequence: untrusted_content, then secret_call
- **Telemetry:** retrieval, tool.result, tool.call
- **Mappings:** ATLAS AML.T0051.001, AML.T0057; OWASP LLM LLM01, LLM02; OWASP Agentic ASI01; ATT&CK none
- **Fixtures:** 1 tp, 5 fp

Fires when untrusted content is followed by any tool call whose arguments are labeled secret, whichever tool it is.

**Hypothesis.** Poisoned metadata can smuggle a secret out through a tool that looks harmless, such as a search query. Requiring untrusted content first and a secret in the arguments should catch that without a list of sink tools.

**Limitations.**

- The secret label on a tool call comes from verbatim matching against known secrets. A transformed secret loses the label and the rule misses.
- It needs no data link from the untrusted content to the call, so an unrelated secret-bearing call after any untrusted read fires.

## Behavior tier

### ADG-0011: Tool chain longer than the dev benign high percentile

- **Version:** 0.1.0 (experimental), **severity:** low
- **Logic:** baseline: chain_length
- **Telemetry:** tool.call
- **Mappings:** ATLAS AML.T0053; OWASP LLM LLM06; OWASP Agentic ASI02; ATT&CK none
- **Fixtures:** 1 tp, 5 fp
- **Fitted:** percentile 95 of matching events per trace = 4, on 91 dev benign traces.
- **Fit command:** `gauntlet fit-baselines --rules rules --traces datasets/corpus/dev/k24 --labels datasets/corpus/labels.jsonl`

Fires when a trace makes more tool calls than the 95th percentile (nearest rank) of tool calls per trace over dev benign traces.

**Hypothesis.** Attacks that probe or loop make more tool calls than ordinary tasks, and the count does not depend on wording, so an upper bound fitted on benign traces should flag them.

**Limitations.**

- By construction about 5 percent of benign traces in the fit population sit at or above the percentile, and long benign chains exceed it. Those are false positives the threshold accepts.
- Most attacks that succeed here use one or two tool calls, well under the threshold, so the rule cannot catch them.
- The threshold reflects one small benign corpus and one model, and will not transfer to an agent with a different tool budget.

### ADG-0012: First use of a privileged tool after untrusted content

- **Version:** 0.1.0 (experimental), **severity:** medium
- **Logic:** sequence: untrusted_content, then first_privileged_call
- **Telemetry:** retrieval, tool.result, tool.call
- **Mappings:** ATLAS AML.T0053; OWASP LLM LLM06; OWASP Agentic ASI02; ATT&CK none
- **Fixtures:** 2 tp, 5 fp

Fires when a write, destructive or outbound tool is used for the first time in the trace after untrusted content has entered it.

**Hypothesis.** Injected content changes what the agent does next. A privileged tool that had not been used before the untrusted content arrived is a behavior change that needs no data link and no wording match, so it should hold where provenance breaks.

**Limitations.**

- A task that legitimately reads an untrusted email and then replies fires. This is the expected false positive of the rule.
- If the tool was already used before the untrusted content arrived, a later malicious use is not a first use and the rule misses it.
- The privileged list is a name pattern, so a renamed tool is not covered. The corpus has only send tools, so the write and destructive names are untested.

### ADG-0013: Rare tool transition relative to the dev benign baseline

- **Version:** 0.1.0 (experimental), **severity:** medium
- **Logic:** baseline: rare_transition
- **Telemetry:** tool.call
- **Mappings:** ATLAS AML.T0053; OWASP LLM LLM06; OWASP Agentic ASI02; ATT&CK none
- **Fixtures:** 1 tp, 5 fp
- **Fitted:** 10 transitions, 153 observed; rare below rate 0.01, on 91 dev benign traces.
- **Fit command:** `gauntlet fit-baselines --rules rules --traces datasets/corpus/dev/k24 --labels datasets/corpus/labels.jsonl`

Fires on each pair of consecutive tool calls, including the first call of a trace, whose share of all transitions in dev benign traces is below 1 percent. Transitions never seen there count as rate 0.

**Hypothesis.** An agent steered off its task takes tool paths ordinary tasks do not, including tools that were never used in benign work. Those paths do not depend on wording.

**Limitations.**

- The fit population is small, so any legitimate transition its tasks never happened to use looks rare and fires. Every fitted transition sits above the 1 percent line, so in practice rare means never seen in the fit.
- With few tools most attack paths reuse common transitions, such as read then send, and do not fire.
- The table holds tool names only. A malicious call through a common transition with hostile arguments looks normal.

### ADG-0014: Access outside the workspace trust boundary

- **Version:** 0.1.0 (experimental), **severity:** high
- **Logic:** match
- **Telemetry:** tool.call, tool.result
- **Mappings:** ATLAS AML.T0057; OWASP LLM LLM02; OWASP Agentic ASI03; ATT&CK T1005
- **Fixtures:** 1 tp, 5 fp

Fires when a file tool argument climbs out of the workspace with a parent path segment, or when a tool result comes back with trust unknown, meaning its source is outside the declared boundary.

**Hypothesis.** An agent that is doing its task stays within the workspace it was given. Reaching beyond it is a privilege change that does not depend on how the request was worded, so it should hold under paraphrase and translation.

**Limitations.**

- An absolute path or a symlink escapes the workspace with no parent segment, and is caught only if the tool result is marked unknown.
- It depends on the sandbox marking trust unknown for out-of-boundary reads; other instrumentation may not make that distinction.
- A legitimate relative path through a parent directory that stays inside the workspace fires.
- Every dev hit involves one literal path, and trust unknown appears only on reads that succeeded, so the dev evidence is one scenario rewritten, not independent escapes.
